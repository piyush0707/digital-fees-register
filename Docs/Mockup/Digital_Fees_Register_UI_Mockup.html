Screen 5 of 8 · The escape-hatch modal (v1)

For the awkward cases — partial, exam, back-fill, void

90% of entries are full monthly tuition paid today — those happen inline on Screen 2 (click cell → Enter). This modal opens only when the Principal taps the ⋯ on a cell: partial payment, exam fee, P.Dues clear, back-fill from the paper register, or voiding an entry. Parents continue to receive the paper Fee Book slip in v1. WhatsApp / Print / Email delivery and the PDF receipt ship in v2.

Fee structure

Accessed via the ⚙ Fee structure button on the Register (beside the class picker). Per-class default fees that the Register reads. Families without a concession use these values; families with a Monthly override (set on their row) ignore them.

Total per year (computed) ₹20,300

How this connects to the rest of the app

  • The Register grid's Monthly anchor cell reads from this table when a family has no concession set.
  • If a family has monthly_fee_override set (via inline edit on the Monthly cell), that override wins — this table is ignored for that family.
  • The Total pending dues calculation on the Dashboard uses the same logic.
  • Past payments records are immutable — changing the fee here only affects future pending calculations.

Student Profile

Opened from the Register by clicking the ✏ edit button on a row. Two-column layout: family fields on the left (shared across all siblings via the families row), student-specific fields on the right. The cyan search bar at the top auto-attaches an existing family; the green banner replaces it once linked.

How the profile connects to the rest of the app

  • Family fields (father, mother, phone, address) live on the families row and are shared by every sibling. Editing them here propagates to every sibling's profile automatically.
  • Student fields (class, DOB, DoA, Aadhaar, PEN) live on the students row. Each sibling has their own.
  • Cyan search bar at top appears when no family is linked yet. Search by father / mother name or 10-digit phone to inherit the family record in one click (also pre-fills all existing siblings).
  • Green linked banner appears when a family is linked. Click the red Unlink button to sever this student from the family.
  • Sibling rows are read-only. To unlink a specific sibling, open their profile and click Unlink there. The → Open profile button jumps to their row.
  • + Add new sibling opens the mini-dialog on Screen 8 — creates a brand-new student in the same family, with auto-assigned roll number.
  • Save validation order: name → at least one parent → DOB → admission → phone (10 digits) → Aadhaar (12 digits). PEN is never validated.
Screen 8 of 8 · Add new sibling

Add New Sibling — Mini Dialog

Opened from the + Add new sibling button inside any Student Profile. Inherits father / mother / phone / address from the parent profile (shown as a read-only banner) and asks only for the new sibling's per-student fields. Roll number is always auto-assigned to the next available in the chosen class.

How "Add new sibling" connects to the rest of the app

  • The inherit banner is informational, not editable. Family fields read directly from the parent profile's families row.
  • Roll number is never typed. The system calls nextRollFor(class) — i.e., SELECT COALESCE(MAX(roll_no), 0) + 1 FROM students WHERE class = $1 — and uses that.
  • On Save: insert a new students row with the parent's family_id + the typed per-student fields. If the new sibling's class matches the currently-active register, inject a row at the bottom with smooth-scroll + yellow highlight.
  • Sibling chips refresh automatically on every visible family member's register row after save — no page reload needed.
  • Validation (v1): only name + class are mandatory; all other fields are optional for now (will be made mandatory in a later iteration). Aadhaar must be 12 digits if entered.
